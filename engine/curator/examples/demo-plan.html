Migrating product search to the new index

Draft plan for review · alt-click anything to annotate · select text to comment · click an option card to decide

Summary

Move product search off the legacy inverted index onto the new vector-hybrid index. The legacy cluster is EOL in Q4; query latency at p99 has degraded 30% year over year. Scope: query path, indexing pipeline, and relevance tests. Out of scope: autocomplete.

Phases

Week 1–2Dual-write to both indexes; backfill historical documents.
Week 3Shadow-read: mirror 100% of queries to the new index, compare results offline.
Week 4–5Serve real traffic from the new index behind a percentage ramp.
Week 6Decommission legacy cluster; remove dual-write.

Risks

High

Relevance regressions are invisible to health checks — a bad ranking ships silently. Mitigation: offline diff of top-10 results on the 500 highest-volume queries before every ramp step.

Medium

Dual-write doubles indexing cost for ~5 weeks. Acceptable, but the backfill must be throttled so it never starves live indexing.

Decision needed: rollout strategy

How should real traffic move to the new index?

Percentage ramp

  • Blast radius capped at each step (1 → 5 → 25 → 100)
  • Relevance diffs checked between steps
  • Two code paths live for ~2 weeks

Cutover with instant rollback

  • One switch, one code path, done in a day
  • Full traffic exposed to any unnoticed regression
  • Rollback restores latency, not user trust
