Approach

Validate maxLength first and throw RangeError when it is below 1 or not an integer. Build the slug exactly as today. If it is longer than maxLength, keep the first maxLength characters and back up to the last whole separator in that window, so neither a word nor a multi-character separator is split. With no separator in the window, keep the hard cut. Then strip a trailing separator with the regex the function already uses.

Steps

  1. Failing tests in test/slugify.test.js: length cap, separator cut, first-word cut, no trailing - or --, RangeError for 0, -1, 2.5 and "10", unchanged output without the option. Verify: npm test fails on the new tests only.
  2. Validation and the cut in src/index.js. Verify: npm test passes, the 5 existing tests included.
  3. Conditional on D-001: test and handling for maxLength: null.
  4. Conditional on D-002: JSDoc @param and README example.

Files touched: src/index.js, test/slugify.test.js, README.md (only if D-002 keeps step 4)

Risks

Medium

A multi-character separator such as -- could leave half a separator at the cut. Step 1 tests it and step 2 backs up to a whole separator.

Low

TypeError for a non-string input and RangeError for a bad maxLength now coexist. Step 1 asserts the exact class.
